# OS-level kill test: TWAP and bulk orders

Run: 2026-11-15T16:58:01.970Z
Node: local anvil fork; NOT mainnet. Throwaway keys, fake ETH, dev-only signer.
Result: **PASS** (8/8 checks)

What this shows: an order runs in a separate worker process that is killed with SIGKILL, once by itself right before a transaction would leave and once from outside right after one was sent. A fresh process started from the saved files finishes the order, and every slice or leg was traded exactly once (checked by wallet nonce). Unlike the in-process restart checks, nothing in memory survives.

## Not covered
- A kill in the middle of a state-file write (the files are written whole each time; a torn write was not simulated).
- A power loss or disk fault: SIGKILL ends the process but the operating system still flushes its file writes.
- The kill happens at two chosen points, not at every possible instruction.
- A live chain; the node here is a local fork and mines every 300 ms.
